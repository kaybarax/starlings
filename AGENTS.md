# Development conventions

- Python package uses `src/starlings`; runtime is stdlib-only, Python >=3.11.
- Run tests: `PYTHONPATH=src python3 -m unittest discover -s tests -v`.
- Build offline from cached pinned build dependencies: `uv build --offline --wheel --out-dir /absolute/external/wheels`.
- Keep temporary environments and acceptance fixtures outside the checkout; build output and bytecode are ignored.
- Write regression tests before implementation where practical. Keep schema and content-ID changes explicit and versioned.
- Milestones 1-4 cover policy/configuration/contracts, local assembly, trusted policy, planning, runs, signed receipts, approvals, journalled promotion and recovery. Only `policy trust` makes a policy trusted (the batch's recorded digest is not trust); only `check` evaluates a receipt; only `promote` advances a gated target, and it alone writes the release branch, always journalling intent before one `git update-ref --stdin` transaction. Revoke and trust must take the same target leases as promotion. Deployment is out of scope. Do not represent diagnostics or coordinator checks as enforcement. Initialization never edits harness instructions or workflows. Milestone 5 qualifies the local product: `examples.py` generates the deterministic offline fixture and `qualification.py` drives disposable authorities through the public CLI only (separate worker OS processes, file barriers, evidence indexes under a caller-chosen root).
- Module ownership: `store.py` (SQLite schema, transactions, leases, request idempotency), `gitops.py` (all Git as argv subprocesses, hooks disabled, file protocol only), `batches.py` (batch/task/lane/stage logic), `verifier.py` (policy trust, planning and selection, receipt checks), `runner.py` (admission, process supervision, guest adapter, evidence and receipt issue), `promotion.py` (approvals, promotion journal and ref transactions, recovery and operator resolution), `enforcement.py` (authority protect hook install, hook check-intent and doctor probe), `signer.py` (ssh-keygen signing), `examples.py` (deterministic example project generator), `qualification.py` (milestone-5 qualification driver and benchmarks), `demo.py` (disposable end-to-end demo behind `starlings demo`), `diagnose.py` (release-failure diagnosis over frozen lane subsets; records only `diagnostic_runs`, never receipts or promotions), `adapters/` (`host.py` adapter contract, routing, disposition and probe helpers; `fake_github.py` deterministic offline host; `github.py` live adapter submitting dispatches through the `gh` CLI — implemented, unqualified; `templates.py` workflow rendering) and `templates/` (packaged GitHub caller and reusable check workflows); keep `cli.py` wiring thin. Exit statuses live in `batches.EXIT`. Candidate processes never receive the signer path or state directory in their environment; never use `shell=True`.
- Runner tests use `tests/test_verifier.py` helpers: tiny poll loops on marker files and the runner hook points `run-started`, `admission-wait`, `admitted`, `process-started`. Guest tests use a fake docker binary; the real parity test needs `STARLINGS_TEST_GUEST_IMAGE` and `STARLINGS_TEST_GUEST_ROOT` (a directory shared with the docker VM).
- Assembly tests build disposable bare authorities in temp dirs via `tests/fixtures.py`; use barriers, hooks and injected clocks, never sleeps. Lease tests inject time through `Store(path, clock)` / `Context(..., clock=...)`. Test hook points: `lane-lease`, `include-before-write`, `include-after-write` (assemble, resolve), `target-lease`, `before-write`, `after-write` (stage and promote). Promotion and recovery tests live in `tests/test_promotion.py`; crash-after-write tests SIGKILL a real subprocess blocked on a FIFO, and lease expiry for recovery is injected with a future store clock.
- Lint: `ruff check .`. Check Git with `git --version` (>= 2.38 required).
- Licensed Apache-2.0. Keep `LICENSE` and `NOTICE` intact. Publication still requires owner authorization.
- README.md is a current-state project guide (what it is, install, quick start, commands, schema essentials, limitations) — never a per-milestone history; milestone evidence, benchmarks and reproduction transcripts go in docs/ (e.g. docs/qualification.md); install and recovery steps live in docs/release-runbook.md.
- At the end of each milestone, commit and push to `origin/main` only after the owner gives the go-ahead for that milestone; never push without it.
- `tests/test_no_private_terms.py` scans tracked files for private markers (home paths, private-key blocks, workspace names). An optional operator denylist extends it from `$STARLINGS_DENYLIST` or `~/.local/state/starlings/denylist.txt`; the denylist stays outside the checkout and is never committed.
- `.gitignore` covers tool caches, `init` tempfiles (`.starlings-*`) and generated artifacts (`bench.json`, `index.json`, `evidence/`); extend it whenever a command or tool can leave new untracked artifacts inside the checkout.
